# X 投稿用のストック

記事への流入をつくるための投稿文。**全 442 記事ぶん、442 本**ある。
API は使わない。書き出したものを X の予約投稿画面に貼る運用。

## なぜ API を使わないか

X は 2026-02-06 に新規開発者向けの無料枠を廃止し、従量課金（Pay Per Use）を既定にした。
**URL を含む投稿は 1 件 $0.20** で、記事リンクを貼る運用だと 1 日 5 件で月およそ $30。
手で予約すれば無料なので、まずはそちらで様子を見る。

## 2 つの流し方

| | 手作業 | ブラウザ自動 |
| --- | --- | --- |
| コマンド | `npm run x:export` | `npm run x:browser` |
| 手間 | 1 本ずつ貼る | 全自動 |
| 費用 | 無料 | 無料 |
| リスク | なし | **規約違反。アカウント凍結の可能性** |

ブラウザ自動は X の規約に反する。使うかどうかは判断のうえで。
壊れたときに気づかず空振りし続けるのを防ぐため、要素が 1 つでも見つからなければ止まる作りにしてある。

## 手作業で流す

```sh
npm run x:validate     # 文字数・記事の実在・重複を検査する
npm run x:export       # 次の 7 日分（35 本）を予約用に書き出す
```

書き出しの先頭に、次に打つコマンドが出る。

```
X 予約投稿用  1 〜 35 本目（全 442 本）
次回は  npm run x:export -- --from 35  から
```

**「どこまで予約したか」は、この `--from` の数字だけで管理する。** 状態ファイルは持たない。
番号を控えておく場所は、メモでもカレンダーでも何でもよい。

### よく使う形

```sh
npm run x:export -- --from 35              # 36 本目から 7 日分
npm run x:export -- --per-day 2            # 1 日 2 本の日付割りにする
npm run x:export -- --count 10             # 10 本だけ
npm run x:export -- --out week1.txt        # ファイルに書き出す
npm run x:export -- --start 2026-09-01     # 日付の起点を変える
```

日付と時刻は**貼るときの目安**。X の画面で予約日時を入れる手間を減らすためのもので、
守らなければいけないものではない。

## 予約のしかた

1. `npm run x:export -- --out week1.txt` で 1 週間分を出す
2. X の投稿画面を開き、書き出しの `---` の下の本文を丸ごと貼る（URL の行まで）
3. 予約アイコンから、書き出しに出ている日付と時刻を入れる
4. 35 本ぶん繰り返す

まとめて予約できる本数には上限があるので、週に一度 30 本前後ずつが回しやすい。
※ 上限の数は変わることがあるので、実際の画面で確認すること。

## ブラウザ自動で流す

### 準備（最初の一度だけ）

Chromium の実行に必要なライブラリを入れる。sudo が要るので手作業で。

```sh
sudo apt-get install -y libnss3 libnspr4 libasound2
```

次に X にログインする。**認証情報はスクリプトでは扱わない。**
開いたウィンドウで手で入れて、以降はそのプロファイルを使い回す。

```sh
npm run x:browser -- --login
```

ログイン情報は `scripts/x/.browser-profile/` に入る。`.gitignore` 済み。**絶対に commit しない。**

### 画面の要素が合っているかを確かめる

**X の UI は変わる。** 変わると要素の指定が外れて動かなくなるので、まずこれを実行する。
投稿はしない。

```sh
npm run x:browser -- --check
```

予約ダイアログのプルダウンが一覧で出るので、`month` `day` `year` `hour` `minute` が
すべて「対応」と出ることを確認する。外れていたら `scripts/x/lib/selectors.mjs` を直す。

### 1 本で試す

```sh
npm run x:browser -- --dry-run --count 1
```

入力まで行い、確定ボタンは押さない。画面を見て、本文と日時が正しく入っていることを確認する。

### 実際に予約する

```sh
npm run x:browser -- --from 0 --count 10
```

- 登録した番号は `.progress.json` に記録され、二重登録を防ぐ
- 1 本ごとに、投稿画面が閉じたことで登録できたかを確かめる。確かめられなければ**その場で止まる**
- 止まったときは画面を `scripts/x/failed-*.png` に保存する
- 1 本ごとに 8〜20 秒あける

一度に大量に流さず、10 本程度ずつ様子を見ながら進めるのが安全。

## 費用をかけない他の選択肢

- **X の標準の予約投稿**（上記）。無料。手間はかかるが確実
- **Buffer / Publer などの無料プラン**。これらは各社が X との間に別枠の取り決めを持つため、
  利用者が投稿ごとの課金を負担しない。ただし無料プランで**予約できる本数には上限**があり、
  条件も変わりやすい。使うなら、現在の無料プランの上限を必ず確認すること
- **API に戻す場合**は、この README の履歴に一式（OAuth 署名・GitHub Actions・費用計算）が
  残っているので、`git log -- scripts/x` から復元できる

## 投稿を足す

`queue.json` の `posts` の**末尾に足す**。途中に挿すと以降の日付割りがずれる。

```json
{ "slug": "243-sheet-metal-unfold", "text": "本文。URL は書かない。" }
```

記事 URL は `slug` から自動で組み立てて末尾に付く。`text` に URL を書く必要はない。

## 検査の中身

`npm run x:validate` は以下を機械的に見る。PR でも走らせられる。

- X の重み付き文字数が 280 を超えていないか（日本語は 1 文字 2、URL は 23 換算）
- `slug` の記事が実在し、下書きでないか
- 同じ記事・同じ本文が二度出てこないか（X は同一本文の連投を弾く）
- 本文に URL が直接書かれていないか
- 同じカテゴリが 3 本以上続いていないか（警告のみ）
